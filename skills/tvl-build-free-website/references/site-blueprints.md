# Site Blueprints

Choose one blueprint for new builds. Keep the first screen useful, not decorative.

## one-page-service

Use for a small company, service, consultant, studio, event, or campaign.

Sections:

- Header with name, navigation, and primary action.
- First viewport: clear offer, audience, proof point, and action.
- Services or outcomes.
- Process or how it works.
- Proof: examples, testimonials, credentials, metrics, or source-backed claims.
- FAQ or objections.
- Contact action.

Files:

- `index.html`
- `styles.css`
- `script.js` only when interaction is needed.
- `images/` for optimized assets.

Quality check:

- Visitor can understand who it is for and what to do next within five seconds.
- Claims are specific and not inflated.
- Contact path works without backend code.

## portfolio-projects

Use for a professional portfolio, creator page, case-study index, or personal site.

Sections:

- Header with name, role, and links.
- First viewport: professional positioning and strongest proof.
- Selected projects or case studies.
- Skills or capabilities.
- About section with relevant credibility.
- Contact and social links.

Files:

- `index.html`
- Optional `projects/<slug>/index.html` pages for case studies.
- `styles.css`
- `images/` for headshot, project images, or diagrams.

Quality check:

- Projects state problem, role, result, and evidence.
- Links to GitHub, LinkedIn, email, or booking path work.
- No private client information is exposed.

## documentation-hub

Use for open source projects, internal public docs, knowledge bases, resources, or skill documentation.

Sections:

- Header with project name, repository link, and navigation.
- First viewport: what the project is and who should use it.
- Quick start.
- Concepts or architecture.
- Guides or examples.
- Reference links.
- Troubleshooting or FAQ.

Files:

- `index.html`
- Optional `docs/<topic>/index.html` pages.
- `styles.css`
- Optional `search.js` only for client-side search.

Quality check:

- A new user can run the quick start without reading the whole site.
- Commands are copyable and accurate.
- Docs match the repository structure.
